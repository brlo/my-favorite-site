# Правила для Claude

## Коммиты и PR

В сообщения коммитов и описания PR не добавлять упоминания об ИИ: никаких `Co-Authored-By: Claude`, `Generated with Claude Code` и т.п.

## Именование

Методы и переменные, возвращающие boolean, называем либо с префиксом `is_` (`is_something`), либо с окончанием `?` (`email_confirmed?`).

## Запуск кода и тесты

Приложение запускается через docker compose up

Ruby и гемы есть только внутри докер-контейнера `bibleox` (код смонтирован в `/app`). На хосте `bundle`/`bin/rails` не работают (нет гемов, rmagick не собирается) — не пытаться ставить их локально, всё запускать так:

```
docker exec bibleox bash -lc 'cd /app && bin/rails test test/services/bible_linker_test.rb'
docker exec bibleox bash -lc 'cd /app && bin/rails runner "puts 1"'
```

Для тестов и `runner` нужны контейнеры `bibpostgres` и `bibredis`. Если они остановлены: `docker compose up -d postgres redis` и подождать несколько секунд.

Тесты ходят в Redis по адресу из `config/settings.yml` (раздел `test`, база 15 в `bibredis`, с паролем как у development; образец в `config/settings.yml.example`). Если адрес пустой, клиент стучится на localhost:6379 и десятки тестов падают с `Redis::CannotConnectError`.

Тесты лежат в `test/` (minitest). Новую логику покрывать тестами рядом с существующими (`test/services`, `test/models`).

## Переводы статей

- Переводы одной статьи связаны общим `group_lang_id`. Текст — только в `body`: главы `<h2>`, абзацы, сноски `[n]` в тексте и `<ol>` с примечаниями в `references`. Поле `verses` (разбивка на строки, как в Библии) устарело — не заполнять.
- Загрузка: YAML в `db/translations/<lang>/` + `bin/rails pages:import_translations FILE=... [DRY_RUN=1] [PUBLISH=1]` (`TranslationImporter`, формат описан в нём). Существующий перевод пропускается, если не указан `update: true`; при смене адреса старый уходит в `redirect_from`. Сначала всегда `DRY_RUN=1`, на проде тоже.
- В меню разделов на проде часто заранее заведены пустые пункты с плохими названиями (кальки с русского вроде «ボゴノセツ», «博戈诺谢茨»). Перед импортом смотреть меню; заготовку с другим названием заполняет и переименовывает `menu: { replace: "старое название" }`.
- Переводить с языка оригинала (греческий, латынь), русский/английский/французский — только как вспомогательные. Расхождения с ними (вставки поздних рукописей и т. п.) — в сносках, а не в тексте. Имена не калькировать с русского: брать формы, принятые в языке перевода и в его Библии на сайте. Терминологию (主教/司祭, 上帝/天主, बिशप/अध्यक्ष…) согласовывать с пользователем на образце до перевода всего объёма.
- Библейские цитаты и ссылки — по переводу Библии языка статьи (`BibleLinker::BIBLE_BY_LANG`: ja → jp-ni, zh-Hans → cn-sb, ko → ko-nkrv, hi → hi-ov, en → en-nrsv). Нумерация псалмов у каждого перевода своя; если цитата у автора по Септуагинте, а перевод с еврейского, — оговорить в сноске.
- В конце `references` — строка об авторе перевода («Родион Власов, с использованием ИИ» на языке перевода), основа текста и вспомогательные переводы. Ссылки на страницы, которых нет на языке статьи, помечать языком страницы.
- Перед выкладкой проверить все ссылки: стих существует в нужном переводе, страница и якорь есть. Якорь заголовка — `HH-` + текст `<h2>`/`<h3>` без знаков препинания, пробелы заменены на `-`.
- Большие переводы удобно собирать скриптом в `tmp/` (в git не попадает), который проверяет сквозную нумерацию сносок и строит YAML; пример — `script/translations/ign/*.py` (послания Игнатия на ja/zh/ko/hi). В `script/translations/` лежат копии рабочих скриптов прошлых переводов (`ign/`, `tert/`, `ja/`, `bible/`, `interlinear/`) как образцы: пути внутри них часто ведут в `tmp/`, а выгрузки чужих текстов (en/fr/la/ru) в git не положены, их при необходимости выгрузить заново.

## Перенос раздела цитат на новый язык

Раздел «Библейские цитаты» — русский список `q`; переводы: `en-q`, `jp_q`, `ko-q`. Эталон — **русская статья**, а не английская: английские бывают старее русских. Перед переводом статьи сравнить с русской структуру (разделы, их порядок, число цитат) и сказать пользователю о расхождениях. Прежде чем заявлять о проблеме в русской статье, проверить её саму: дубли и пропуски обычно есть только в переводах.

Инструменты — в `script/translations/`, исходники статей — в `db/translations/LANG/src/`:

- `bin/rails runner script/translations/view_q.rb LANG file:q_x` (или `db`, или путь статьи) — компактный вид: структура английской статьи, выделения, стихи целевой Библии. Стихов с английским текстом в выводе нет, поэтому цитаты не калькируются.
- `db/translations/LANG/src/NAME.txt` — исходник статей на разметке, она описана в шапке `script/translations/q_build.rb`. Цитата пишется как ссылка и выделяемые фразы: `> mf 16:19 :: фраза :: !фраза с mark ~~ примечание`.
- `bin/rails runner script/translations/q_build.rb LANG db/translations/LANG/src/NAME.txt` строит `db/translations/LANG/q_NAME.yml`: текст стихов подставляется из базы дословно, каждая выделенная фраза проверяется по стиху. Фразу, которой нет в стихе, скрипт считает ошибкой и YAML не пишет.
- Ссылки на ещё не переведённые статьи писать `[[ru:путь|текст]]` или `[[en:путь|текст]]` (сборщик найдёт русскую страницу). Их потом заменяет `bin/rails pages:relink_translations LANG=.. LIST=..`: сперва пройти все статьи, затем перелинковать, якоря при этом пропадают.
- Папки меню — отдельный файл `db/translations/LANG/q_00_folders.yml`, загружается первым.
- Правки уже загруженных статей: YAML остаётся источником правды, `bin/rails runner script/translations/q_sync.rb LANG FILE [path]` заносит его в базу, потом снова перелинковка (после неё тексты в базе и в YAML отличаются ссылками). Без `update: true` импорт существующую статью молча пропускает.
- Проверка: `bin/rails runner script/translations/chk_q.rb LANG FILE` (стихи, пометки языка). Обложки — `copy_cover: true`: файл копируется в `public/s` на той машине, где идёт импорт, в git картинки не попадают. Недостающие обложки добирает `bin/rails runner script/translations/copy_covers.rb LANG [LIST] [DRY_RUN]`; картинки внутри текста переносятся вручную, в компактном виде они отмечены `IMG`.

Подводные камни:

- Смотреть особенности Библии языка на месте, а не по памяти. В ko-nkrv (개역개정) нет второканонических книг (перевод с греческого с пометкой, `||| gr ref`), NT по критическому тексту: на месте Мф 17:21, Мк 11:26, Деян 8:37 и др. стихов нет; диапазон сдвигать так, чтобы нужные слова попали в цитату. Цитаты вставляются как есть (하나님), в своём тексте статей — 하느님; имена в своём тексте — по 개역개정 (바울, 누가, 고린도).
- Где перевод Библии искажает смысл, на котором держится довод (`προέγνω`, «врата ада», `αἱρέσεις`), — короткое примечание с греческим, текст стиха не менять.
- NT в `gr-lxx-byz` и `gr-ru` — критический текст, а не византийский. Утверждения о византийском чтении проверять только по CSV Робинсона–Пирпонта (`github.com/byztxt/byzantine-majority-text`).
- Страница со слишком коротким `body` (меньше 40 символов) отдаёт 404: у страницы-списка должно быть нормальное вступление.
- Новые переводчики терминов согласовывать на пилоте из нескольких статей, затем закрепить словарь и держать его одинаковым по всем партиям.

## Обновление отдельной статьи на проде

Статья вне YAML (или правка, не связанная с импортом) обновляется прямо в базе, по шагам:

1. Выгрузить текущий `body` с прода и строить новый текст только от этой выгрузки.
2. Локально: собрать новый HTML скриптом, проверить парность тегов, ссылки на удалённые якоря, стихи; посмотреть страницу.
3. Перед записью сравнить MD5 `body` на проде с выгрузкой: если статью успели поправить, сначала слить правки. Пользователь вычитывает статьи прямо на сайте, поэтому правки бывают.
4. Скрипт приезжает на прод с деплоем; если он ещё не задеплоен — `scp` на сервер и `sudo docker cp` в `/app/script/translations/`. Новый текст подать в STDIN: `ssh bibleox "sudo docker exec -i bibleox bash -lc 'cd /app && bin/rails runner script/translations/page_update.rb LANG PATH tmp/backup.html'" < new.html`. Скрипт сохраняет старый `body` в указанный файл.
5. Проверить живую страницу `curl`-ом и назвать пользователю путь бэкапа.

Запись на прод — только по явному подтверждению с названной операцией, в том числе когда локально всё готово. Составную команду с записью на прод не склеивать с локальными шагами: при отказе не выполнится ничего. Не коммитить и не деплоить без команды.

## Переводы Библии

- Источник — модули MyBible с https://www.ph4.ru/b4_my.php (номера книг MyBible = `BOOKS[..][:id]`). Загрузка: `bin/rails bible:import_mybible FILE=... TR=код [FIX='a=b']`; убрать стихи, которых нет в модуле: `bible:prune`; перевести ссылки статей со старого перевода на новый: `bible:relink`; удалить перевод: `bible:delete`.
- Новый код перевода прописать: `config/initializers/constants.rb`, 22 файла `config/locales/*.yml` (`bib_translations` и названия в `breadcrumbs.bib_langs`), `app/views/verses/_text_bar.html.erb`, список в поиске, поисковые сервисы (CJK-языки), `BibleLinker`, `mobile/src/lib/config.js`, список переводов на `/about` (`app/views/pages/about.html.erb`).
- Модули не всегда честные: бывают пустые заглушки, правки составителя (в корейском 공동번역 «침례» вместо «세례»; в 개역개정 NRKV лишняя «”» в Быт 1:1, импорт с `FIX='”='`); отрывки в скобках (Мк 16:9-20, Ин 5:3-4, Ин 7:53-8:11) размечены незакрытым `<n>[` … `]</n>`, до исправления `MybibleImporter.clean` конечные стихи стирались — недостающие добавляет `script/translations/bible/fix_brackets.rb`, стихи чужого языка на месте недостающих. Проверять текст выборочно до импорта.
- Файлы модулей (`tmp/bibles/`) в git не попадают: на прод копировать через `scp` и `docker cp` в `/app/tmp/bibles`.

## Прод и деплой

- Прод: `ssh bibleox`. Сайт: https://bibleox.com/
- Деплой: `bin/bib_deploy.sh`. На сервере он делает `git reset --hard origin/main`, поэтому сначала запушить в main. Алиасы `bib_*` лежат на сервере в `~/.bib_aliases.sh`, в репозитории их нет.
- Контейнер работает от uid 1000 / gid 1001. Если git на сервере запускается от root, файлы переходят к root, и `bundle install` падает с ошибкой записи в `Gemfile.lock`. Алиас `bib_update_code` сам возвращает владельца `1000:1001`; руками git на сервере лучше не гонять от root без `chown`.
- Статику (`/assets/...`) отдаёт отдельный хост `res.bibleox.com`
