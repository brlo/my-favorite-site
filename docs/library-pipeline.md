# Новый язык в святоотеческой библиотеке — точка входа

Этот файл читается **первым**, если задача звучит как «перевести отцов на X»,
«добавить авторов в раздел», «синхронизировать меню библиотеки с русским»,
«сделать страницу автора». Он короткий; детали — по ссылкам в конце.

Главное правило: **не писать новый конвейер**. Для en/ja/ko/la/fr всё уже
устроено; новый язык повторяет ту же схему.

## 1. Эталон — русский раздел

- Страница-список: `church_writers` (ru). Авторы — `page_type 4`, труды —
  `page_type 1`; труды являются **детьми страницы автора** (`parent_id = автор`).
- Авторская страница — полный перевод русского эталона (`body`), а не
  сокращённый пересказ. `title`, `title_sub`, `meta_desc` — с эталона.
- Меню: века — папки в меню списка; авторы — пункты в этих папках; труды —
  в **меню самой страницы автора** (`menus.page_id = автор`), а не в меню списка.
- Обложка, «золотые» пункты (`is_gold`), `seo_kind`, место в веке — тоже с
  русского эталона.

## 2. YAML: на автора два файла

1. `<author>_author.yml` — `list: <путь списка раздела>`,
   `menu: { parent: "<папка-век>", replace: "<старая заготовка>" }`.
2. `<author>_works.yml` — `list: <путь автора>`,
   `folders: [{ path: "<категория>", priority: 1 }]`,
   у трудов `menu: { parent: "<категория>" }`.

Так `TranslationImporter` сам создаёт труды детьми автора и кладёт пункты в
меню автора. Отдельный «переносчик» меню не нужен.

Готовые примеры прямо в репозитории:
`db/translations/fr/cl_00_author.yml` + `cl_01_cor1.yml`,
`db/translations/fr/ignatius_author.yml`, `pl_01_phil.yml`.

Подробно: `docs/latin-library-plan.md` (раздел про два YAML),
`docs/english-library-project.md`, `docs/japanese-translations.md`.

## 3. Импорт

```bash
bin/rails pages:import_translations FILE=db/translations/<lang>/<author>_author.yml DRY_RUN=1
bin/rails pages:import_translations FILE=... PUBLISH=1
# затем works.yml, тоже DRY_RUN=1 → PUBLISH=1
```

Порядок: сначала автор, потом труды. `update: true` — только если страница уже
есть и её надо обновить; после импорта флаг снять.

## 4. Метаданные — существующими скриптами

Источник/переводчик — в `references`, не в `body` после `<hr>`.

| Что | Чем |
|---|---|
| Обложка (+ оверлеи) | `copy_cover: true` в YAML автора или `script/translations/copy_covers.rb LANG` |
| «Золотые» пункты | `script/translations/gold.rb LANG` (зеркалит `is_gold` по `group_lang_id`) |
| `seo_kind` | `script/seo/backfill_seo_kind.rb`, при необходимости `mark_seo_kinds_pass2.rb` |
| Меню по векам (все авторы, заготовки) | `script/translations/fill_library_menus.rb LANG [APPLY=1] [RESET=1]`, данные — `db/translations/library_menu_*.yml` |
| Структура `links_XX` | `docs/menu-structure.md`, `script/translations/links_structure.rb` |

`fill_library_menus.rb` без `RESET` только дополняет и обновляет место/
`priority`/`is_gold`; `RESET=1` удаляет пустые заготовки под списком (папки и
пункты с `path` не трогает) и строит меню заново по снимку RU.

## 5. Проверка перед выкладкой

- `bin/rails runner script/translations/check_library_structure.rb LANG` —
  ловит труд под списком вместо автора, пункт труда в меню списка, автора с
  трудами без меню и дубли пунктов.
- Все страницы отдают 200; у труда в хлебных крошках есть автор
  («… » Автор » Труд»), `parent_id` труда = автор.
- На странице автора есть меню с трудами, а не только «Похожие материалы».
- Обложка видна, «золотые» пункты совпадают с RU, число авторов по векам
  совпадает с RU.
- Нет кириллицы в тексте перевода, ссылки/якоря живы, сноски сквозные.
- Пункты-заготовки без страницы — серые, без `path`, не ведут на 404.

## 6. Красные флаги

- Один YAML на автора и труды с `list: <раздел>` и последующим переносом меню.
- Собственный скрипт «перенести меню», «скопировать обложки», «зеркалить
  золото» — всё это уже есть (см. таблицу).
- Заголовки/подзаголовки/обложки «от себя», а не с RU-эталона.
- Массовое переименование или удаление чужих пунктов меню без согласования.
- Импорт на прод без `DRY_RUN=1` и без явной команды пользователя.


## 8. Труды без RU-эталона и меню по книгам

- Если у труда **нет RU-страницы**, не подставлять чужой `src`: импортёр
  привяжет текст к неправильной группе. Использовать
  `script/translations/de/import_external_works.rb` (DE-only страница,
  HTML-тела — в `db/translations/de/external/`, источник — в `references`).
  Это исключение, а не замена обычному двум-YAML конвейеру.
- «Пересказы» и фрагменты не выдавать за полный труд: пример — «Панарион»
  Епифания, где BKV даёт только `Anakephalaiosis` и Haer. 78; такие вещи
  лучше не публиковать.
- Верхние категории автора — `mirror_author_folders.rb`; дубли-заготовки —
  `cleanup_duplicate_authors.rb`; части книг — `restructure_chrysostom_nt.rb`
  и `group_author_parts.rb`.
- Для французских меню: `script/translations/fr/fix_chrysostom_menu.rb`,
  `fix_tertullian_menu.rb` — оставлять только французскую часть названия,
  части книг группировать под книгой.
- После любых правок меню: `check_library_structure.rb LANG`, 200 на
  страницах, отсутствие кириллицы/латинских дублей в меню.
