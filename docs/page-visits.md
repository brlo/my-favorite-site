# Статистика посещений

Счётчики в Redis (`app/services/page_visits.rb`), дневные ключи с TTL 7 дней. Заполняются JS-маячком: Stimulus-контроллер `visit_beacon` на каждый показ страницы шлёт POST `/visit` (`VisitsController` → `PageVisits.beacon_visit`). Так засчитываются только клиенты, исполнившие JavaScript, — скрейперы, тянущие голый HTML (в т.ч. распределённые ботнеты «одна страница с IP»), статистику не двигают.

- Маячок подписан токеном `PageVisits.visit_token(page_id)` (HMAC от id статьи, 0 — для нестатейных страниц), без токена `/visit` отвечает 422. Токен не привязан к дате и IP, чтобы не ломаться о кеш и смену адреса; его задача — подтвердить, что отправитель получил страницу сайта.
- Дневные ключи: `vis`/`s-vis`/`b-vis` (люди/подозрительные/боты), `uip` (уникальные IP), `bots` (по именам), `langs` (языки интерфейса), `zips` (топ IP), `top` (топ статей). Сводка `/admin` показывает их за сегодня (незакрытые сутки: цифры растут до полуночи по Москве) и за вчера (сутки закрыты, числа не меняются) — пишутся и читаются одни и те же ключи, различается только дата.
- Счётчик просмотров статьи (`vis:PAGE_ID`) тоже двигает только маячок (`register_visit`), боты по `BotDetector` его не увеличивают; метка `vis:PAGE_ID=IP` на 12 часов защищает от повторных засчитываний. На странице счётчик выводится через `page_count` — только чтение.
- Ботов определяет `BotDetector`: гем `browser` + кастомный список `CUSTOM_BOTS` для тех, кого гем не знает (кандидатов искать в access-логах прода: `/var/log/nginx/access.log.1` и в блоке «Топ IP» сводки).
- «Подозрительные» — не-бот IP, сделавший за день больше `SUSPICIOUS_DAY_LIMIT` запросов (ловит headless-браузеры, которые JS исполняют).
- Ограничения: посетители с выключенным JS и часть блокировщиков в статистику не попадают (как и в Яндекс.Метрике). Накопленные ранее счётчики просмотров статей содержат ботовские накрутки — задним числом не исправляются.

## «Читают сейчас»

- Живые отметки лежат в zset `reading` (`PageVisits::READING_KEY`): член `PAGE_ID:хэш_IP` для страницы и `b:КОД_ПЕРЕВОДА:КОД_КНИГИ:хэш_IP` для главы Библии. Score — время последнего heartbeat, отметка живёт `READING_WINDOW` (15 минут). Читатель в нескольких вкладках в общий счётчик попадает один раз, но в счётчике каждой страницы — по разу.
- Heartbeat шлёт Stimulus-контроллер `visit_beacon`: первую отметку ставит сразу при показе страницы, дальше подтверждает её раз в 45 секунд, пока вкладка видима. Для статьи — `POST /reading` с `page_id` и токеном статьи (её же сразу отмечает и маячок `/visit`), для главы Библии — с `book`, `lang` (код перевода) и токеном `PageVisits.bible_visit_token(book)`. Глава не передаётся: в блоке показывается только книга, но по языку перевода строятся пометка языка и ссылка на главу. `leave: 1` снимает отметку при переходе или закрытии вкладки.
- Блок «Читают сейчас» (`NewsController#prepare_reading_now`) показывает топ страниц **всех языков** (у иноязычных — пометка языка) и топ книг Библии; у книг название локализуется через `books.full`, иноязычный перевод получает пометку языка, а ссылка ведёт на первую главу книги в этом переводе. Общий счётчик — уникальные читатели по всему сайту, поэтому список и счётчик сходятся (кроме топа: в списке не больше `READING_LIMIT` строк).
- Сводка `/admin` показывает то же самое: страницы всех языков и книги Библии.

## Читатели переводов Библии

- Отдельного запроса нет: счётчик двигает тот же heartbeat главы (`/reading` с `book`, `lang` и токеном книги). `touch_bible_reading` после проверки книги вызывает `register_bible_visit`, так что веб и мобильное приложение (`/api/offline/reading`) учитываются одинаково.
- Метка `bvis:<код перевода>=<IP>` на 12 часов: один читатель учитывается в переводе один раз, сколько бы глав он ни открыл и сколько бы heartbeat'ов ни прислал. Ботов отсекает `BotDetector` в контроллере до вызова, `leave` счётчик не двигает.
- Ключи: `vis:b:<код перевода>` — всего читателей перевода (хранится постоянно, как счётчики статей), `btop<дата>` — дневной топ переводов (TTL 7 дней, как остальная дневная статистика).
- Пока цифры видны только в сводке `/admin`: блок «Переводы Библии» показывает всего, сегодня и вчера по каждому переводу. Публичного счётчика нет; при желании его можно вывести в списке выбора перевода (`bible_translation_count`).
- Цифра — это читатели перевода, а не просмотры глав: переходы по главам её не раздувают, зато она не покажет, сколько раз открывали конкретную главу.

## Мобильное приложение

Приложение шлёт те же сигналы отдельными запросами через `/api/offline`:

- `POST /api/offline/visit` — показ страницы; токен приходит вместе с текстом (`GET /api/offline/pages`) или добирается `GET /api/offline/tokens?ids=...` для уже скачанных страниц. Обработчик — `Api::VisitsController`, дальше тот же `PageVisits.beacon_visit`.
- `POST /api/offline/reading` — heartbeat «читает сейчас», пока статья открыта (раз в 45 секунд), и `leave: 1` при уходе. Для главы Библии — `book`, `lang` + `PageVisits.bible_visit_token(book)`. Обработчик — `Api::ReadingsController`, дальше `PageVisits.touch_reading` / `clear_reading` или `touch_bible_reading` / `clear_bible_reading`.

Офлайн-чтение в статистику не попадает: дневные счётчики и «Читают сейчас» привязаны ко времени, и отложенная отправка исказила бы сводку. Токен маячка не привязан ко времени, поэтому его можно хранить на устройстве.
