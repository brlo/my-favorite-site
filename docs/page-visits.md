# Статистика посещений

Счётчики в Redis (`app/services/page_visits.rb`), дневные ключи с TTL 7 дней. Заполняются JS-маячком: Stimulus-контроллер `visit_beacon` на каждый показ страницы шлёт POST `/visit` (`VisitsController` → `PageVisits.beacon_visit`). Так засчитываются только клиенты, исполнившие JavaScript, — скрейперы, тянущие голый HTML (в т.ч. распределённые ботнеты «одна страница с IP»), статистику не двигают.

- Маячок подписан токеном `PageVisits.visit_token(page_id)` (HMAC от id статьи, 0 — для нестатейных страниц), без токена `/visit` отвечает 422. Токен не привязан к дате и IP, чтобы не ломаться о кеш и смену адреса; его задача — подтвердить, что отправитель получил страницу сайта.
- Дневные ключи: `vis`/`s-vis`/`b-vis` (люди/подозрительные/боты), `uip` (уникальные IP), `bots` (по именам), `langs` (языки интерфейса), `zips` (топ IP), `top` (топ статей). Сводка — `/admin`.
- Счётчик просмотров статьи (`vis:PAGE_ID`) тоже двигает только маячок (`register_visit`), боты по `BotDetector` его не увеличивают; метка `vis:PAGE_ID=IP` на 12 часов защищает от повторных засчитываний. На странице счётчик выводится через `page_count` — только чтение.
- Ботов определяет `BotDetector`: гем `browser` + кастомный список `CUSTOM_BOTS` для тех, кого гем не знает (кандидатов искать в access-логах прода: `/var/log/nginx/access.log.1` и в блоке «Топ IP» сводки).
- «Подозрительные» — не-бот IP, сделавший за день больше `SUSPICIOUS_DAY_LIMIT` запросов (ловит headless-браузеры, которые JS исполняют).
- Ограничения: посетители с выключенным JS и часть блокировщиков в статистику не попадают (как и в Яндекс.Метрике). Накопленные ранее счётчики просмотров статей содержат ботовские накрутки — задним числом не исправляются.
