# Контроль качества перевода раздела цитат (приёмка партии)

Как доводить перевод раздела «Библейские цитаты» (`q-saints` → `en-saints-q`, `ko-q`, `cn-q`, …) до эталона и принимать партию перед выкладкой.
Дополняет `docs/quotes-section.md` (инструменты сборки `q_build` и механика раздела) и `docs/translations.md` (общие правила перевода).
Проверено на партии EN «Священное Писание» (12 статей: 9 правок после GLM + 3 новых, 2026-11).
Долгосрочный план и статус EN-проекта (какие папки сделаны, что дальше, журнал партий) —
`docs/english-quotes-project.md`; общий план двух EN-треков — `docs/english-translation-plan.md`.

## Главный принцип

**Эталон — русская статья**, а не предыдущий перевод. Английская (или иная) страница должна повторять её:
структуру (заголовки, порядок цитат, абзацы, списки), рисунок выделений (strong/mark/em),
ссылки и подписи — но английский текст цитат берётся из готовых переводов библиотеки сайта (`q-saints-en`), если они там есть.
Нельзя «подгонять» текст перевода под теги и нельзя терять выделения ради дословности библиотеки: если библиотечный
текст не совпадает с RU по смыслу выделения — либо берём перевод с RU и снимаем библиотечную ссылку (подпись текстом),
либо оговариваем расхождение в notes. Ссылка на библиотеку при несовпадающем тексте — дефект.

## Критерии приёмки (для каждой статьи)

1. **Счётчики разметки** совпадают с RU: `blockquote`, `strong`, `mark`, `em`, `h2`, `h3`, `ul`, `ol`, `li`, `p`,
   а также число абзацев **внутри** цитат.
2. **Рисунок выделений**: по каждой цитате совпадают `[strong, mark, em, u, вложенных strong>mark]`, а в идеале и
   последовательность открытия/закрытия `strong/mark/em/u` (допустимое исключение — другой порядок слов в переводе,
   тогда расхождение выносится в предупреждения и проверяется глазами).
3. **Заголовки** — та же последовательность уровней `h2/h3/h4`; века, имена и даты переведены в стиле раздела.
4. **Ссылки**:
   - ссылки на стихи RU → `https://bibleox.com/<lang>/<code>/<book>/<ch>/#L…` с подписью-названием книги языка
     (EN: `eng-nkjv`, Сирах — `en-nrsv`; подпись `Sir.`);
   - ссылки на труды отцов → английская страница библиотеки (`/en/en/w/…`), только если текст цитаты реально есть на этой странице;
   - внешние `azbyka.ru` в перевод не переносятся; ссылки на русские статьи допустимы только с `lang="ru"`
     (когда английской страницы нет), лучше — простым текстом;
   - все стихи существуют в БД целевой Библии, все страницы библиотеки существуют.
5. **HTML**: теги сбалансированы, нет сырой разметки (`::`, `**`, `[[`, `|||`), нет литеральных `<…>`
   (только `&lt;…&gt;`), нет пустых абзацев.
6. **Текст**: без тегов не меняется относительно предыдущей версии, кроме осознанных исправлений (ошибки, пропуски);
   для цитат из библиотеки — дословно, допустимы только типографика/сноски.
7. **Смысловая верность заимствованного перевода**: если английский перевод (библиотеки или Библии)
   скрывает мысль, ради которой цитата стоит в статье, — найден другой перевод, либо дано примечание
   с оригиналом (греч./лат./евр.), либо цитата заменена; молча оставлять нельзя, текст чужого перевода
   не правится. Проверяется на ревью отдельным пунктом.
   Порог — только смысл, на котором держится довод статьи; мелкие стилистические отличия не комментируются.

## Инструменты

```bash
# паритет + ссылки по YAML-партии (главная приёмка)
bin/rails runner script/translations/q_parity.rb en db/translations/en/q_saints_1.yml
bin/rails runner script/translations/q_parity.rb en db/translations/en/q_saints_1.yml --summary
bin/rails runner script/translations/q_parity.rb en db/translations/en/q_saints_1.yml --links
bin/rails runner script/translations/q_parity.rb en db/translations/en/q_saints_1.yml --spans   # RU | EN по каждой цитате для глазами-сверки
bin/rails runner script/translations/q_parity.rb en db/translations/en/q_saints_1.yml --draft tmp/q_batch/<папка>/out  # черновики статей до сборки в YAML

# инвентарь долгосрочного проекта: что готово/осталось по папкам
bin/rails runner script/translations/q_inventory.rb en en-saints-q --folders
bin/rails runner script/translations/q_inventory.rb en en-saints-q --next

# подготовка партии: выгрузка RU-эталона, текущего EN и ссылок в tmp/q_batch/<папка>/
bin/rails runner script/translations/q_batch.rb export en en-saints-q "Бог"

# сборка партии: применить черновики tmp/q_batch/<папка>/out в YAML
bin/rails runner script/translations/q_apply.rb en db/translations/en/q_saints_2.yml tmp/q_batch/бог

# компактный вид статей для перевода/сборки
bin/rails runner script/translations/view_q.rb en file:q_saints_1

# сборка YAML из разметки и проверка стихов (см. docs/quotes-section.md)
bin/rails runner script/translations/q_build.rb en db/translations/en/src/name.txt
bin/rails runner script/translations/chk_q.rb en db/translations/en/q_name.yml

# обновление уже импортированных страниц из YAML
bin/rails runner script/translations/q_sync.rb en db/translations/en/q_saints_1.yml [path…]

# новые страницы (importer сам создаёт папки и меню; is_published: true — публиковать)
bin/rails runner -e 'puts TranslationImporter.call(YAML.load_file("db/translations/en/q_saints_1.yml"), is_published: true)'

# обложки
bin/rails runner script/translations/copy_covers.rb en en-saints-q
```

`q_parity.rb` при расхождениях выходит с кодом 1, предупреждения о несовпадении порядка тегов при равных счётчиках
(другой порядок слов) — отдельным списком, без падения; `--strict` считает их ошибками.

## Процесс партии

1. **Инвентаризация.** Сравнить RU и перевод: какие статьи есть/нет, счётчики, пропуски, ссылки.
   Большие статьи (>20 цитат, >50 КБ) дробить по `<h2>`-границам между исполнителями.
2. **Данные для работы.** Выгрузить в `tmp/` тела RU (из БД) и текущие тела перевода (из YAML), ссылки RU.
3. **Перевод/правка по статье.** Исполнитель пишет **только тело** статьи в отдельный файл (`tmp/.../out/<path>.html`),
   итерируя `q_parity.rb` до состояния «все счётчики как в RU, таблица по цитатам без расхождений». YAML и БД исполнитель не трогает.
4. **Независимое ревью.** Отдельный агент сверяет по `--spans`/тексту: смысловые границы каждого выделения, дословность
   библиотечных цитат, подписи/якоря, потери текста, HTML. Отчёт — список замечаний, без правок; затем правки вносит
   автор статьи или ведущий.
5. **Сборка YAML** ведущим (один писатель на файл): применить тела, прогнать `q_parity.rb`, `q_sync` в локальную БД.
6. **Проверка на локальном сервере**: страницы и список раздела отдают 200, выделения на странице совпадают с расчётными,
   пункты меню и «золотые» пункты на месте.
7. **Выкладка** (только по явной команде пользователя) — см. ниже.
8. **Отчёт**: сколько статей, восстановлено тегов, пропусков, откуда взяты цитаты, остаточные сомнения.

## Делегирование и параллельность

- Один агент — 1–2 статьи (или часть большой статьи); каждому — свой выходной файл, чтобы не конфликтовать.
- Обязательно дать агенту: путь RU-эталона, текущий EN-файл, отчёт по ссылкам, команду проверки и критерий приёмки
  («счётчики совпадают, таблица по цитатам без `*`, баланс тегов OK, текст меняется только осознанно»).
- Максимум 8 одновременно активных агентов; при лимите — ставить в очередь следующие статьи.
- Итог агента: кратко, что добавлено/исправлено и что осталось под сомнением; подробности — в notes-файл.
- Все находки ревью сохранять в файлах (например `tmp/…/review/<path>.md`), чтобы не терять контекст между раундами.

Шаблон задания исполнителю:

```
Эталон RU: tmp/q_fix/ru/<src>.html
Текущий перевод: tmp/q_fix/out/<path>.html (или en_orig)
Проверка: ruby tmp/q_fix/check.rb <path> (счётчики, заголовки, рисунок по цитатам, текст)
Задача: привести к паритету с RU — заголовки, число цитат, списки, абзацы;
восстановить strong/mark/em по смыслу; добавить ссылки на стихи и библиотеку;
прочитать текст против RU и исправить явные ошибки. YAML/БД/git не трогать.
```

## Подводные камни (из практики)

- **Дословность библиотеки.** Страница библиотеки может содержать только часть труда (`0kMl_The_Stromata_7` — главы 1–9,
  а цитаты из гл. 17) или другой перевод. Перед постановкой ссылки убедиться, что цитируемый фрагмент есть на странице;
  иначе — подпись текстом.
- **Библиотечный текст нельзя «причёсывать».** Замена слов ради гладкости (`which` → `her`, `rewards God` → `in God`),
  выкинутые слова, перестановка реплик — дефект, даже если записан в notes: читатель видит изменённый чужой перевод.
  Если фраза не передаёт мысль — перевод с RU без ссылки или примечание переводчика вне кавычек; текст чужого перевода
  не правится (опечатки — сохранять или чинить осознанно с оговоркой в статье).
- **Пустые теги ради счётчика.** Пустые `<strong> </strong>`/`<em> </em>` допустимы только как воспроизведение
  артефакта RU (рендер их срезает); добавлять их от себя, чтобы сойтись в счётчиках, нельзя — подбирайте естественное
  слово под выделение или меняйте границу фразы.
- **RU-перевод бывает шире/уже библиотечного** (вставки, сокращения `<…>`). Не выдавать перевод с RU за библиотечный;
  выбор («библиотечный текст» или «перевод с RU») фиксировать в notes.
- **Разная нумерация**: Псалмы (синодальный N → английский N+1: `Ps. 33:9` → `Ps. 34:8`; `Ps. 142:10` → `Ps. 143:10`),
  Сирах (`en-nrsv` не совпадает с синодальным: `Sir. 22:12-14` ≈ NRSV 22:13). В разделе EN принята русская нумерация
  как конвенция — новую статью лучше приводить к английской и явно отмечать.
- **LXX-чтения**: в Притч. 9:18 вторая половина стиха есть в Синодальном, но отсутствует в NKJV — нужна оговорка в цитате.
- **Опечатки библиотеки** (`Mere`=Mem, `Paraleipomenä`, `1 Cor. 13.28` вместо 12:28) — сохранять или исправлять осознанно,
  с пометкой в notes.
- **Пустые артефакты** `<strong> </strong>` в RU-заголовках: рендер их срезает, но они входят в счётчики. Для паритета
  можно воспроизвести (невидимы) или убрать и зафиксировать расхождение; главное — не забыть.
- **Порядок слов**: если в переводе фраза перестроена, точный рисунок тегов недостижим — счётчики сохранять, расхождение
  последовательности отмечать и проверять границы по смыслу.
- **Разбивка на абзацы** внутри цитат — часть структуры: `</p><p>` вставляется по границам RU без изменения текста.
- **`Page#body` нормализуется при сохранении** (`render_body`): YAML и БД различаются пробелами/переносами. Сравнивать
  тела для проверки надо БД↔БД (локальная/прод), а не YAML↔БД.
- **Локаль `books.short` содержит тонкий пробел U+200A** («2 Thess») — обычные проверки подписей дают ложные срабатывания.
- **YAML.dump переформатирует файл целиком** — большой дифф это нормально; главное, чтобы `q_parity.rb` был чист.
- **Не коммитить чужие незакоммиченные файлы** в `db/translations/` и не импортировать их.
- **Не забыть про `lang="ru"`** у ссылок на русские статьи; иначе `q_parity.rb` справедливо ругается.
- **Черновики и скрипты** держать в `tmp/` (gitignored), в репозиторий — только YAML и этот инструмент.

## Выкладка партии на прод (только по явной команде пользователя)

1. `git add` только нужный YAML → коммит (без упоминаний ИИ в сообщении) → `git push origin main`.
2. `bin/bib_deploy.sh` (сайт должен ответить 200; рестарт puma может занять до ~2.5 минут — скрипт ретраит).
3. `scp` YAML и скрипт импорта на сервер → `docker cp` в `/app/tmp/` → импорт с `is_published: true`
   (на проде `RAILS_ENV=production`, БД `bibleox_production`). Для уже существующих страниц в YAML должен быть `update: true`.
4. Зеркалировать «золотые» пункты меню (`menus.is_gold`) с русских статей по `group_lang_id`
   (переводы — отдельные пункты меню, `is_gold` у них не наследуется).
5. `copy_covers.rb LANG LIST`.
6. Сверить число страниц перевода с эталоном по `group_lang_id` (ловит молча пропущенные YAML).
7. Проверить живые страницы: 200, число strong/mark/em, список раздела, отсутствие плейсхолдеров `[[`.
8. Сравнить `md5(body)` локальной и прод-БД (убедиться, что импортировано ровно то, что проверяли).
9. Если в телах есть плейсхолдеры `[[ru:…]]`/`[[en:…]]` — после импорта `bin/rails pages:relink_translations LANG=.. LIST=..`;
   при абсолютных ссылках (как правило) перелинковка не нужна.

## Чек-лист приёмки

- [ ] `q_parity.rb LANG FILE` → «Паритет с RU и ссылки: OK» (предупреждения просмотрены).
- [ ] `--spans` выборочно (или ревьюером) сверены границы выделений по каждой цитате.
- [ ] Все библиотечные цитаты совпадают с текстом страницы библиотеки, на которую ведёт ссылка.
- [ ] Все ссылки на стихи существуют; подписи — по названиям книг языка; azbyka нет; `ru/ru` только с `lang="ru"`.
- [ ] Заголовки/порядок авторов/абзацы/списки совпадают с RU.
- [ ] Локальный сервер: страницы и список раздела 200; меню, «золотые» пункты, обложки.
- [ ] Тексты в изменённых местах прочитаны против RU (нет потерь смысла), notes обновлены.
- [ ] Прод: число страниц, `is_published`, md5 тел, живые 200.
