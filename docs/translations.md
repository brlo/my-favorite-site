# Переводы статей

Рабочая инструкция для агентов при переводе/правке статей (в т.ч. через импорт YAML). Для китайского проекта см. также `docs/chinese-translations.md`.

- Переводы одной статьи связаны общим `group_lang_id`. Текст — только в `body`: главы `<h2>`, абзацы, сноски `[n]` в тексте и `<ol>` с примечаниями в `references`. Поле `verses` (разбивка на строки, как в Библии) устарело — не заполнять.
- Загрузка: YAML в `db/translations/<lang>/` + `bin/rails pages:import_translations FILE=... [DRY_RUN=1] [PUBLISH=1]` (`TranslationImporter`, формат описан в нём). Существующий перевод пропускается, если не указан `update: true`; при смене адреса старый уходит в `redirect_from`. Сначала всегда `DRY_RUN=1`, на проде тоже.
- В меню разделов на проде часто заранее заведены пустые пункты с плохими названиями (кальки с русского вроде «ボゴノセツ», «博戈诺谢茨»). Перед импортом смотреть меню; заготовку с другим названием заполняет и переименовывает `menu: { replace: "старое название" }`.
- Переводить с языка оригинала (греческий, латынь), русский/английский/французский — только как вспомогательные. Расхождения с ними (вставки поздних рукописей и т. п.) — в сносках, а не в тексте. Имена не калькировать с русского: брать формы, принятые в языке перевода и в его Библии на сайте. Терминологию (主教/司祭, 上帝/天主, बिशप/अध्यक्ष…) согласовывать с пользователем на образце до перевода всего объёма.
- Библейские цитаты и ссылки — по переводу Библии языка статьи (`BibleLinker::BIBLE_BY_LANG`: ja → jp-ni, zh-Hans → cn-sb, ko → ko-nkrv, hi → hi-ov, en → en-nrsv). Нумерация псалмов у каждого перевода своя; если цитата у автора по Септуагинте, а перевод с еврейского, — оговорить в сноске.
- В конце `references` — строка об авторе перевода («Родион Власов, с использованием ИИ» на языке перевода), основа текста и вспомогательные переводы. Ссылки на страницы, которых нет на языке статьи, помечать языком страницы.
- Перед выкладкой проверить все ссылки: стих существует в нужном переводе, страница и якорь есть. Якорь заголовка — `HH-` + текст `<h2>`/`<h3>` без знаков препинания, пробелы заменены на `-`.
- Большие переводы удобно собирать скриптом в `tmp/` (в git не попадает), который проверяет сквозную нумерацию сносок и строит YAML; пример — `script/translations/ign/*.py` (послания Игнатия на ja/zh/ko/hi). В `script/translations/` лежат копии рабочих скриптов прошлых переводов (`ign/`, `pol/`, `tert/`, `ja/`, `bible/`, `interlinear/`) как образцы: пути внутри них часто ведут в `tmp/`, а выгрузки чужих текстов (en/fr/la/ru) в git не положены, их при необходимости выгрузить заново.
- Греческие термины, обсуждаемые в статье, писать по-гречески (ἄρτος, ἄζυμα); русская транслитерация — только в русских статьях.
- Импортер не перемещает пункты меню между папками (только путь/заголовок): при переносе статьи в другой раздел править `menus.parent_id` руками.

## Обновление отдельной статьи на проде

Статья вне YAML (или правка, не связанная с импортом) обновляется прямо в базе, по шагам:

1. Выгрузить текущий `body` с прода и строить новый текст только от этой выгрузки.
2. Локально: собрать новый HTML скриптом, проверить парность тегов, ссылки на удалённые якоря, стихи; посмотреть страницу.
3. Перед записью сравнить MD5 `body` на проде с выгрузкой: если статью успели поправить, сначала слить правки. Пользователь вычитывает статьи прямо на сайте, поэтому правки бывают.
4. Скрипт приезжает на прод с деплоем; если он ещё не задеплоен — `scp` на сервер и `sudo docker cp` в `/app/script/translations/`. Новый текст подать в STDIN: `ssh bibleox "sudo docker exec -i bibleox bash -lc 'cd /app && bin/rails runner script/translations/page_update.rb LANG PATH tmp/backup.html'" < new.html`. Скрипт сохраняет старый `body` в указанный файл.
5. Проверить живую страницу `curl`-ом и назвать пользователю путь бэкапа.

Запись на прод — только по явному подтверждению с названной операцией, в том числе когда локально всё готово. Составную команду с записью на прод не склеивать с локальными шагами: при отказе не выполнится ничего. Не коммитить и не деплоить без команды.
