# Перевод современных диспутов с протестантами

Регламент для перевода полемических статей современных авторов — диспутов
православных с протестантами и близких жанров. Сложился на диспутах о.
Евгения Веселова с баптистами: RU 536–540,554,4380 (автор 535) → EN
530–534,555,4399 (переведены заново 2026-11) и JA 6691–6697 + автор (2026-11).
Рассчитан на повторное использование для новых статей и языков. Общие
правила — `AGENTS.md` и `docs/translations.md`; здесь — специфика жанра,
глоссарии EN/JA и конвейер. Языковые глоссарии отцов (более традиционная
лексика) — в docs по языкам.

## Общие принципы жанра

- **Переводить заново с RU-оригинала**, не править старый машинный черновик:
  правка стоит столько же (каждый абзац всё равно сверять), а тихие ошибки
  (перевранные ссылки, смешение терминов, расплющенные blockquote) остаются.
- Структурные элементы (blockquote, rutube-вставки, метки спикеров,
  разметка strong/em) восстанавливать программно из RU-body.
- Аудитория — не-православные: ключевые православные термины получают
  глоссу в скобках при **первом упоминании в каждой статье** (не один раз на
  весь корпус!). После сборки глоссы проверять пакетно по всем статьям.
- После сборки сверять плотность «вставных слов» (хеджи/коннекторы) с
  RU-оригиналом — модели добавляют тики (см. «Уроки»).
- Цитаты Библии — дословно из Библии языка статьи (NKJV / 新共同訳)， славянизмы
  и церковнославянские цитаты RU-оригинала для ja транслитерировать катаканой
  (кириллица в ja-тексте запрещена).
- Страница автора: EN → EN-раздел авторов (528), JA → 著者出版物 (4591) —
  **не** раздел отцов; плюс пункт в меню раздела (JA: группа 著者原稿).
  `title` — чистое имя, без суффиксов хлебных крошек.
- Прод: md5-сверка RU-оригинала с выгрузкой перед записью (`length()` в
  Postgres считает символы, файлы — байты; у psql-выгрузки хвостовой `\n`);
  прод-id ≠ dev-id — страницы искать по path, не по id.

## Библейские ссылки

- **EN**: полные названия книг, диапазоны en dash, места через «; » —
  простым текстом, линкер сам поставит ссылки (ведёт на en-nrsv). Текст
  цитат выверять под **NKJV** (`verses`, tr_code='eng-nkjv'; коды книг
  транслитом). Расхождение «цитата NKJV vs ссылка en-nrsv» — допустимо; для
  строгого паритета — явные eng-nkjv-ссылки. Псалмы: русская (LXX) нумерация
  пересчитывается в еврейскую по сверке (нелинейно, не автоматизировать):
  Пс.50:7→Psalm 51:5, Пс.5:8→5:7, Пс.6:6→6:5, Пс.113:25→115:17, Пс.145:3→146:3.
  1Цар→1 Samuel, 2Цар→2 Samuel, 3Цар→1 Kings, 4Цар→2 Kings; Сир→Sirach,
  Прем→Wisdom (нумерация совпадает).
- **JA**: jp-ni (新共同訳)， дословно по базе; furigana-скобки (初[はじ]め)
  выкидывать. Ссылки писать сразу ja-текстом （マタ. 10:38; 16:24; 11:12），
  продолжения без книги допустимы; сокращения — ABBR из
  `script/translations/ign/ja_common.py`. Псалмы: 新共同訳 считает надписание
  стихами 1–2 — каждая ссылка сверяется individually (Пс.50:7→詩51:7); только
  через проверенную карту PSALM_MAP.

## Оформление

- **EN**: кавычки “...”, внутренние ‘...’; тире — em dash с пробелами; реплики
  жирной меткой **Orthodox:** / **Baptist:** / **Baptist pastor:** /
  **Orthodox priest:**; «Комментарий:» — blockquote **Comment:**;
  вступительный блок *Participants in the dispute:*; rutube-ссылки
  сохраняются; h2 диспутов: «Report of the Orthodox side (…)», «Report of
  the Baptist side (…)», «Discussion of the reports».
- **JA**: заголовки «Тема ―― 正教徒とバプテスト派の対談»; метки и 註 — выше;
  типографика полная ширина; кириллица = 0 (вне URL).

## Конвейер (рабочие скрипты — `script/translations/veselov/`)

1. `extract.py <ru_id>` — выгрузка абзацев RU в JSON (тип p/bq/h2, метка
   спикера, текст). Метки распознаются в вариантах `<strong>Метка:</strong>`,
   `<strong>Метка</strong>:`, blockquote `<p><strong>Комментарий.</strong>…`.
2. Перевод батчами ~55 абзацев → `<lang>_<id>_b*.json` ({idx: текст}); для EN
   ссылки токенами `{Jn3:5}`, для JA — сразу ja-текстом; разметка
   strong/em переносится содержательно.
3. `build.py <ru_id>` — сборка `body_<lang>_<id>.html` с валидатором:
   полнота абзацев 1:1, кириллица=0 (вне href/URL), парность тегов, все
   реф-группы в допустимых форматах (ABBR), псалмы только через PSALM_MAP.
   Сбой генерации (мусор вроде «ore» внутри слов) обходить сборкой абзаца из
   нескольких коротких литералов + проверка перед dump.
4. `PID=<id> FILE=… bin/rails runner …/update_dev.rb` — заливка в dev с
   бэкапом; просмотр `/ru/<lang>/w/<path>` (префикс `/ru/` на dev
   обязателен для EN, для JA работает и `/ja/ja/`).
5. Прод: md5-сверка, тела через `page_update.rb <lang> <path> tmp/backup.html`
   (текст по ssh stdin), заголовки `titles_prod.rb` (scp + docker cp +
   runner). Живые проверки: 200, комментарии, rutube, глоссы, метки.

## Уроки (из EN- и JA-проектов Веселова)

- Легитимные совпадения с «плохими» словами проверять контекстом: business в
  «бизнес/командировка» — не термин «дела».
- Seed-перевод оставляет тики: ご存じのとおり ×212 при 58 хеджах в RU — после
  сборки чистить правилом «хедж/коннектор max 1 на абзац, если в RU их
  меньше» (итог 212→26); しかも ×125→34.
- Глоссы-конвенцию проверять по ВСЕМ статьям пакетно, не по памяти (в
  проекте применились только к первой статье).
- 像的 — не слово: «образное» = 比喩的， но противопоставление притчи и образа =
  象徴; соблазн = つまずき (誘惑 = искушение).
- Прод-id ≠ dev-id (у Веселова JA автор 6686/6690): все прод-скрипты ищут по
  path; menu-ids могут совпадать — не рассчитывать.
- `title` без суффиксов: сайт сам строит `<title>` из хлебных крошек.
- Для JA-авторов (современных) раздел 著者出版物， не раздел отцов.
