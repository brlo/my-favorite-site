# EN-проект: святоотеческая библиотека (труды отцов)

Долгосрочный проект перевода святоотеческой библиотеки на английский: страницы авторов и их
произведений. Образец методики для других языков — `docs/japanese-translations.md` (там же
конвейер, автонумерация сносок, ревью, меню-заготовки); ko/ar — `docs/korean-translations.md`,
`docs/arabic-translations.md`. Общий план двух EN-треков — `docs/english-translation-plan.md`;
раздел цитат — `docs/english-quotes-project.md`.

## Что переводим

- RU-эталон: список **`church_writers`** (id 363) «Труды древних святых отцов и церковных
  писателей»: папки веков меню → страницы авторов (`page_type 4`) → труды (`page_type 1`).
- EN-список: **`q-saints-en`** (id 391) «Works of the ancient Holy Fathers and Church Writers»;
  папки веков: 1st … 20th century + `Collections`, `Catechism`.
- Задача EN-проекта: довести английскую библиотеку до полноты относительно RU-эталона:
  страницы отсутствующих авторов и недостающие труды. Уже существующие EN-страницы
  (ANF/NPNF и др. переводы) не переписывать без нужды — новые страницы добавлять рядом.

## Источники текста (политика EN)

Приоритет для каждого труда:
1. **Уже есть EN-страница** (ANF/NPNF/Roberts-Donaldson и др.) — сохранять, только связать
   с RU-группой/menu и при необходимости нормализовать оформление; заново не переводить.
2. **Готовый английский перевод в общественном достоянии** (ANF/NPNF, Roberts-Donaldson,
   Lightfoot, Wensinck, Mason и т.п.) — брать дословно, указать источник в `references`
   и в примечаниях; проверить, что текст действительно есть (CCEL/archive.org и т.п.),
   и не нарушать авторские права (только public domain/разрешённые тексты).
3. **Перевод с оригинала** — если на сайте есть `grc`/`la`-страница труда (греческий/латынь),
   переводить с неё; иначе с критического издания (указать издание) или с RU
   (для русских авторов и трудов, известных только в русском переводе).
RU — вспомогательный ориентир; EN/другие языки — тоже вспомогательные. Кальки с русского
не допускать; имена — в формах, принятых в английской традиции и в eng-nkjv.

**Смысловая верность заимствованного перевода.** Если готовый английский перевод (ANF/NPNF и
др.) не передаёт мысль, ради которой цитата/фрагмент важны (термин, игра слов, LXX-чтение,
догматический оттенок), нельзя ни молча оставлять, ни править чужой текст: сверить с
оригиналом (`grc`/`la`), при необходимости взять другое издание/перевод; если такого нет —
перевести самому с оригинала (пометив, что перевод наш) либо дать примечание с оригинальным
словом/чтением. Для цитат на странице автора — те же правила, что в
`docs/english-quotes-project.md` («Если заимствованный перевод скрывает мысль оригинала»).

Наличие оригиналов проверять: `library_status --authors` показывает для каждого автора
число трудов с `grc`- и `la`-страницами на сайте. Если оригинала на сайте нет — решить,
создавать ли `grc`/`la`-страницу (как в ja-проекте) или ссылаться на издание.

## Структура и конвенции EN-страниц

Брать образцом живые EN-страницы библиотеки (напр. `Ignatius_of_Antioch_Theophorus` +
труды, `irenaeus-against-heresies-b3`).

- **Страница автора** (`page_type 4`): `title` — имя первым, затем век/краткая идентификация:
  `Ignatius of Antioch (Theophorus), 1st c.`; `title_sub` — чин/даты/кафедра:
  `hieromartyr (~35-107), bishop of Antioch, disciple of the apostle John`.
  Тело: `<h2>Biography</h2>` (житие, память, цитаты о нём/из его трудов), при необходимости
  h3-темы; цитаты из трудов — дословно из EN-переводов этих трудов (можно assert в сборщике);
  структуру сверять с RU-страницей автора (порядок разделов, полнота).
- **Страница труда** (`page_type 1`): главы — `<h2>N</h2>` (прескрипт = глава 0, именованные
  главы допустимы); абзацы внутри главы нумерованные: `<p>1. …</p>` (даёт цитирование
  глава:абзац); сноски `[n]` по порядку + `<ol><li><p>…</p></li></ol>` в `references`
  (нумерация — сборщиком, не руками).
- **Ссылки на Писание**: явные `<a href="https://bibleox.com/en/eng-nkjv/<book>/<ch>/#L<lines>">…</a>`
  (Сирах — `en-nrsv`, подпись `Sir.`); текст — по eng-nkjv, при LXX-чтении — оговорка в сноске.
  Псалмы: пересчитывать в еврейскую нумерацию и сверять каждый стих по БД (сдвиг нелинейный).
- **Ссылки на другие страницы**: абсолютные `https://bibleox.com/en/en/w/<path>#HH-<anchor>`;
  на свой труд — `#HH-<глава>`; страницы, которых нет на EN, — с пометой (en)/(ru) по конвенции
  `docs/translations.md`.
- **`references`**: в конце — `ol` со сносками и строка принципов: переводчик (Родион Власов,
  с использованием ИИ), основа (издание/рукопись), вспомогательные переводы, Библия, что
  сделано с LXX-нумерацией/латинскими главами; важные решения — и в самих сносках.
- **Путь (URL)**: новые страницы — kebab-case (`anthony-the-great`,
  `isaac-the-syrian-ascetical-homilies`), `path_low` уникален глобально; старые пути не менять.
  Авторы — `имя-эпитет` (`anthony-the-great`), труды — `<автор>-<труд>`.
- **Меню**: автор — пункт века (`menu: {parent: "4th century", replace: …}`); труды — пункты
  под страницей автора (`list: <author path>`), серии/части — через `folders:`; порядок —
  priority как в RU/логике издания. Заготовки с плохими названиями заменять (`replace`).
- **Обложки** — `copy_cover`, если у RU-страницы есть обложка.

## Конвейер на автора (адаптация ja-схемы)

1. **Инвентарь:** `library_status.rb en --works "<автор>"` — труды, наличие EN/grc/la,
   объёмы; сверить вручную с меню/страницами (членение трудов!).
2. **Источники:** для каждого труда выбрать tier (см. выше), выписать издание/перевод
   и где взят текст; проверить права.
3. **Сборщики:** скрипты — в `tmp/en_fathers/<author>/` (в git не попадают; после коммита
   копию в `script/translations/`), по образцу `script/translations/ign/` (hi/ja/ko-версии)
   и `pol/`, `did/`: сборка YAML, автонумерация сносок, assert полноты абзацев/структуры,
   проверка кириллицы = 0, подстановка ссылок, проверка вхождения цитат в авторской странице.
4. **YAML:** `db/translations/en/<author>_*.yml`, `list: q-saints-en` (автор) /
   `list: <author path>` (труды); `DRY_RUN=1` → просмотр → `PUBLISH=1`.
5. **Проверки:** рендер `http://localhost/ru/en/w/<path>`, все ссылки/анкоры живы, стихи
   существуют, сноски сквозные, структура страницы автора соответствует RU,
   цитаты на странице автора дословно входят в тексты трудов.
6. **Ревью вторым агентом:** оригинал/источник + конвенции + глоссарий; P1/P2/P3-отчёт;
   правки → пересборка → реимпорт (в YAML ставится `update: true`, после импорта флаг снять).
7. **Коммит/деплой** — только по команде: push → `bin/bib_deploy.sh` → импорт YAML на проде
   (`DRY_RUN=1`, затем `PUBLISH=1`), проверка 200/меню/сносок/обложек.
8. **Статус:** обновить таблицу «Статус» (вверху) и «Журнал» ниже в этом файле.

## Риски и подводные камни

- **Членение трудов у языков разное**: не гнаться за числом страниц; критерий — доступность
  содержания, а не 1:1 по страницам. Перед автором сверять состав трудов вручную.
- **Старые EN-страницы** — другой перевод и оформление (plain-текст ссылки, без явных `<a>`);
  не ломать существующие якоря и меню, не переписывать текст без нужды.
- **Авторские права**: только public domain или разрешённые тексты; сомнительное — уточнять
  у пользователя.
- **Нумерация глав/стихов**: у каждого издания своя; фиксировать в сносках, что взято.
- **Сноски**: только автонумерация сборщиком; правки вручную ломают сквозную нумерацию.
- **Меню-заготовки**: `replace` — точное старое название; после импорта проверить, что
  заготовка заполнена, а не создан дубль.
- **Правки пользователя на сайте святы**: перед правкой опубликованной страницы сверить
  `md5(body)`; после правок пользователя не перетирать title/меню.
- **Импортёр не перемещает пункты меню между папками** — перенос делать SQL по `menus.parent_id`.
- **Деплой по старому коммиту** при сбое push — проверять `git log` на сервере.

## Как продолжить (короткая версия)

1. `library_status.rb en --gaps` → выбрать автора (по порядку веков и объёму).
2. `library_status.rb en --works "<автор>"` → список трудов и наличие EN/grc/la.
3. Определить источники по каждому труду; собрать YAML-сборщиком (tmp → script/).
4. Импорт на dev (`DRY_RUN=1` → `PUBLISH=1`), проверки, ревью.
5. Выкладка по команде; обновить статус/журнал в этом файле (таблицы «Статус» и «Журнал»
   правятся в том же коммите, что и партия, — иначе следующая сессия потеряет контекст).
