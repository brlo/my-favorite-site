# Структура меню раздела «Предание» (links_XX)

Меню раздела «Предание» — это пункты таблицы `menus` с `page_id` страницы-списка
`links_<locale>` (`page_type = 4`). Оно одинаково устроено во всех языках:
переводятся только названия, а структура (группы, вложенность, порядок) берётся
от русского эталона `links_ru`. Расхождения ловит и по возможности исправляет
`script/translations/links_structure.rb`.

Проверка всех языков (ничего не пишет, exit 1 при отклонениях):

```
docker exec bibleox bash -lc 'cd /app && bin/rails runner script/translations/links_structure.rb'
```

Проверка/план и выравнивание одного языка:

```
docker exec bibleox bash -lc 'cd /app && bin/rails runner script/translations/links_structure.rb LANG=zh-Hant'
docker exec bibleox bash -lc 'cd /app && bin/rails runner script/translations/links_structure.rb LANG=zh-Hant APPLY=1'
```

Без `APPLY=1` скрипт считает план в транзакции с откатом: он показывает, что
создаст/перенесёт/переставит, но в БД ничего не записывает. `APPLY=1` пишет;
лишние пункты скрипт не удаляет и существующие названия не переименовывает —
только создаёт недостающие, переносит к правильному родителю, проставляет
`priority` и заполняет `path` у заготовок.

## Эталонное дерево

```
links_XX
├── Библиотека [1]
│   ├── 📚 Труды древних святых отцов и церковных писателей — church_writers [1]
│   ├── 📃 Соборы — Вселенские_Соборы [2]
│   ├── 🖼️ Иконы — древние-иконы [3]
│   ├── 🪨 Храмы — Древние_христианские_храмы [4]
│   ├── Христианские захоронения и надписи — KPgB_Христианские_захоронения_и_надписи [5]
│   ├── 📜 Библейские манускрипты — библейские_манускрипты [6]
│   ├── 🙏 Молитвы — молитвы [7]
│   ├── 🎵 Музыка — православная_музыка [8]
│   └── 🍞 Постная кухня — 2NCD_Постная_кухня [9]
├── Цитатники [2]
│   ├── 📜 Цитаты библейские — q [1]
│   └── 📖 Цитаты святых отцов — q-saints [2]
└── Статьи о Писании и Предании [3]
    └── 📄 Авторские публикации — authors [1]
```

Путь в правой колонке — путь **русской** страницы-раздела. В языке перевода
пункт ведёт на страницу с тем же `group_lang_id`, поэтому путь перевода может
отличаться (`q` → `cn-q` / `tw-q`, `authors` → `作者專欄` и т. п.). Порядок
пунктов задаёт `priority`; в эталоне это 1..9 внутри «Библиотеки», 1..2 в
«Цитатниках», 1 в «Статьях». Числа в русской БД могут быть разрежены
(1, 2, 3, 4, 5, 8, 10, 13, 15) — важен порядок, а не сами числа.

## Правила

1. **Три группы, 9/2/1.** В корне меню ровно три пункта без `path`; в
   «Библиотеке» девять детей, в «Цитатниках» два, в «Статьях» один. Группа —
   это пункт с `path IS NULL`, на него нельзя ссылаться.
2. **Нет перевода — заготовка.** Если раздела на языке ещё нет, пункт остаётся
   с переведённым названием и пустым `path` (в меню он серый, некликабельный,
   как `大公会议` в zh-Hans). Когда страница появляется, `path` заполняется у
   того же пункта — импортёр ищет заготовку по названию (`menu: { replace: … }`
   для старого названия).
3. **Путь не переводить и не менять.** `path` берётся у страницы перевода;
   URL раздела — часть контракта. Меняется только подпись пункта.
4. **Названия — на языке перевода**, по терминологии языка; эмодзи — как в
   эталоне (📚 📃 🖼️ 🪨 📜 🙏 🎵 🍞 📖 📄). Новый язык добавляется в `TITLES`
   в `script/translations/links_structure.rb`; после этого `APPLY=1` разложит
   пункты по эталону. Уже существующее название на сайте без нужды не
   переименовываем (эмодзи может не быть — это не структурное отклонение).
5. **Никаких лишних корневых пунктов.** Языковые материалы, которых нет в
   русском эталоне, кладутся внутрь третьей группы («Статьи о Писании и
   Предании»), а не в корень. Так сделано в ja (`著者出版物` и языковые статьи).
6. **Правки пользователя святы.** Скрипт не удаляет пункты и не переименовывает
   существующие; если на сайте пункт переименован или добавлен вручную, сначала
   сверьтесь с пользователем, потом меняйте структуру.
7. **После любой правки меню** запускайте проверку: она печатает дерево
   отклонившегося языка и список отклонений.
