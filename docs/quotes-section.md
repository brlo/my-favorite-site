# Перенос раздела цитат на новый язык

Раздел «Библейские цитаты» — русский список `q`; переводы: `en-q`, `jp_q`, `ko-q`, `cn-q`. Эталон — **русская статья**, а не английская: английские бывают старее русских. Перед переводом статьи сравнить с русской структуру (разделы, их порядок, число цитат) и сказать пользователю о расхождениях. Прежде чем заявлять о проблеме в русской статье, проверить её саму: дубли и пропуски обычно есть только в переводах. Когда раздел выходит на новом языке — добавить ссылку на него в `public/llms.txt` (коллекции цитат).

Инструменты — в `script/translations/`, исходники статей — в `db/translations/LANG/src/`:

- `bin/rails runner script/translations/view_q.rb LANG file:q_x` (или `db`, или путь статьи) — компактный вид: структура английской статьи, выделения, стихи целевой Библии. Стихов с английским текстом в выводе нет, поэтому цитаты не калькируются.
- `db/translations/LANG/src/NAME.txt` — исходник статей на разметке, она описана в шапке `script/translations/q_build.rb`. Цитата пишется как ссылка и выделяемые фразы: `> mf 16:19 :: фраза :: !фраза с mark ~~ примечание`.
- `bin/rails runner script/translations/q_build.rb LANG db/translations/LANG/src/NAME.txt` строит `db/translations/LANG/q_NAME.yml`: текст стихов подставляется из базы дословно, каждая выделенная фраза проверяется по стиху. Фразу, которой нет в стихе, скрипт считает ошибкой и YAML не пишет.
- Ссылки на ещё не переведённые статьи писать `[[ru:путь|текст]]` или `[[en:путь|текст]]` (сборщик найдёт русскую страницу). Их потом заменяет `bin/rails pages:relink_translations LANG=.. LIST=..`: сперва пройти все статьи, затем перелинковать, якоря при этом пропадают.
- Папки меню — отдельный файл `db/translations/LANG/q_00_folders.yml`, загружается первым.
- Правки уже загруженных статей: YAML остаётся источником правды, `bin/rails runner script/translations/q_sync.rb LANG FILE [path]` заносит его в базу, потом снова перелинковка (после неё тексты в базе и в YAML отличаются ссылками). Без `update: true` импорт существующую статью молча пропускает.
- Проверка: `bin/rails runner script/translations/chk_q.rb LANG FILE` (стихи, пометки языка). Обложки — `copy_cover: true`: файл копируется в `public/s` на той машине, где идёт импорт, в git картинки не попадают. Недостающие обложки добирает `bin/rails runner script/translations/copy_covers.rb LANG [LIST] [DRY_RUN]`; картинки внутри текста переносятся вручную, в компактном виде они отмечены `IMG`.

Подводные камни:

- Смотреть особенности Библии языка на месте, а не по памяти. В ko-nkrv (개역개정) нет второканонических книг (перевод с греческого с пометкой, `||| gr ref`), NT по критическому тексту: на месте Мф 17:21, Мк 11:26, Деян 8:37 и др. стихов нет; диапазон сдвигать так, чтобы нужные слова попали в цитату. Цитаты вставляются как есть (하나님), в своём тексте статей — 하느님; имена в своём тексте — по 개역개정 (바울, 누가, 고린도).
- Где перевод Библии искажает смысл, на котором держится довод (`προέγνω`, «врата ада», `αἱρέσεις`), — короткое примечание с греческим, текст стиха не менять.
- NT в `gr-lxx-byz` и `gr-ru` — критический текст, а не византийский. Утверждения о византийском чтении проверять только по CSV Робинсона–Пирпонта (`github.com/byztxt/byzantine-majority-text`).
- Страница со слишком коротким `body` (меньше 40 символов) отдаёт 404: у страницы-списка должно быть нормальное вступление.
- Новые переводчики терминов согласовывать на пилоте из нескольких статей, затем закрепить словарь и держать его одинаковым по всем партиям.

Механика `q_build` (актуально для любой партии):

- Текст цитаты `>` всегда берётся из Библии языка целиком (все указанные стихи); каждый сегмент после `::` — это выделение (без `!` — жирный, с `!` — жирный+mark), а не «какую часть цитировать». Цитата без выделений — просто `> ref`. Номера стихов первого ref задают текст, остальные refs только подписываются.
- `<<`/`>>` обрезают весь склеенный текст цитаты сразу (нельзя обрезать один стих внутри мультистиховой цитаты — тогда цитировать без обрезки). `locate()` не находит фразы с «」『』〔〕» и через издательские скобки вида 〔有古卷…〕 — брать подстроки без скобок либо ставить сноску.
- Строка цитаты должна начинаться с `>`: подпись на той же строке («向以利沙：> 4ts 2:15 :: …») молча превращается в абзац с сырой разметкой в YAML, `chk_q` это не ловит. Проверять YAML на `:: !` внутри `<p>`.
- Нумерация стихов в переводах «плавает»: если стих не найден — проверить соседей, прежде чем считать его отсутствующим. Псалмы: синодальный N → еврейский N+1. Сирах: синодальный → 思高 сдвигами (4:32→4:33, 7:15→7:16, 20:24→20:26, 35:17→35:21 и др.). Местами стихи слиты в предыдущий (Лк 1:2, Числ 30:3→30:2, Ис 65:7→65:6 в cn-cuv) — тогда диапазоны с пропуском вида `iez 18:2-10,12-30`.
- Второканоника в cn-cuv нет: Сирах, Премудрость, Дан 14, Товит и т. д. — только литеральной формой `| текст ||| sb …` (текст по 思高本). Послание Иеремии, 2–3 Ездры нет ни в одной китайской редакции — свой перевод с пометкой `ru`.
- Греческие термины, обсуждаемые в статье, писать по-гречески (ἄρτος, ἄζυма); русская транслитерация — только в русских статьях.
- Импортер не перемещает пункты меню между папками (только путь/заголовок): при переносе статьи в другой раздел править `menus.parent_id` руками.

Заливка партии переводов на прод (порядок): scp YAML → `docker cp` в `/app/tmp/…` → флаг `update: true` впрыскивать скриптом in-memory (sed по YAML ломал структуру) → импорт каждой партии с `PUBLISH=1` → `bin/rails pages:relink_translations LANG=.. LIST=..` → `script/translations/copy_covers.rb LANG` → зеркалирование золотых пунктов меню (`menus.is_gold`) на переводы по `group_lang_id`: золотой пункт русской статьи → пункт перевода. После импорта сверить число страниц перевода с эталоном по `group_lang_id` — ловит пропущенные YAML (импорт без флага молча пропускает). Чужие незакоммиченные файлы в `db/translations/` (слепые сравнения других ИИ) не импортировать и не коммитить.
