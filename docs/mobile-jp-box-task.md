# Задача для отдельной сессии: разметка jp-box в мобильном приложении

Промт для новой сессии. Контекст: перевод `jp-box` (японский, 77 книг) в вебе
рендерится особым образом, а мобильное приложение (`mobile/`, Vue 3) показывает
текст как есть — с сырыми маркерами. Нужно довести рендер до веб-поведения.

## Что видно сейчас

В тексте стихов jp-box используются маркеры, которые веб разворачивает на сервере
(`app/helpers/application_helper.rb`), а мобильное приложение — нет:

| маркер | пример | что должно быть |
|---|---|---|
| `漢字[かな]` | `主[しゅ]`, `恵[めぐ]み` | `<ruby>漢字<rt>かな</rt></ruby>` |
| `{A｜B}` | `{聖霊[せいれい]｜聖神[せいしん]}` | показывать A; B — при включённой кальке |
| `{{n}}` | `…の内[うち]{{1}}にある` | сноска-звёздочка, по нажатию — текст из `verse.data.notes[n]` |
| `<j>…</j>` | слова Иисуса | красный цвет |
| `<mo>…</mo>` | слова Богородицы | синий цвет |
| `<br>` | абзацный разрыв (Сир 1:1) | перенос строки |
| `〔…〕` | `〔主[しゅ]である〕` | остаются как текст, без изменений |

## Где смотреть

- Веб-эталон: `app/helpers/application_helper.rb` — `jp_box_text` (калька `{A|B}` и
  замена имён при кальке), `wrap_bible_notes` (`{{n}}` → `.bib-note` с `data-tip`),
  `verse_text_for_display`; вьюхи `app/views/verses/`.
- Фуригана в вебе приходит уже разобранной в HTML (`<ruby>`); в API — смотри, что
  реально отдаётся в JSON для главы (поле текста стиха), и отталкивайся от этого.
- Мобильное приложение: `mobile/src/views/BibleChapter.vue` (глава и стихи),
  `mobile/src/lib/` (запросы к API), `mobile/src/styles.css`.

## Что сделать

1. Найти, где мобильный клиент выводит текст стиха, и добавить преобразование
   маркеров jp-box **только для `tr_code == 'jp-box'`** (другие переводы не трогать).
2. Фуригана: `漢字[かな]` → `<ruby>`; следить, чтобы не ломались скобки `〔…〕`,
   сноски `{{n}}` и уже существующая разметка `<j>/<mo>`.
3. Сноски: `{{n}}` → маркер `＊`; по тапу показывать `data.notes[n]` (тултип/поповер,
   как в вебе). Если API не отдаёт `notes`, проверить сериализатор и добавить поле.
4. Калька `{A｜B}`: по умолчанию A; если в приложении есть переключатель
   традиционной лексики — использовать B, иначе просто A (сырые скобки не показывать).
5. `<j>` — красный, `<mo>` — синий, `<br>` — перенос; стили — в `styles.css`,
   согласованно с вебом.
6. Проверить на живых главах: `mf/1` (НЗ, `<j>`), `ps/50` (ВЗ, фуригана), `prsir/1`
   (`<br>`), `is/53` (без красного), `3ezd/7` (длинная глава), `dan/3` (песнь отроков).
7. Регрессия: другие переводы (`jp-ni`, `ru`, `csl-ru`, `gr-lxx-byz`) выглядят как
   раньше; десктопный код (`app/`) не меняется.

## Запреты

- Не менять тексты переводов и не трогать `db/translations/`, `app/`, `docs/`
  (кроме правок самого мобильного приложения).
- Не деплоить без отдельной команды; сборка мобильного — по инструкции в `mobile/`.

## Отчёт

Что изменено, как проверено (скриншоты/URL), какие главы смотрел, что осталось
(например, если API не отдаёт `notes`).
